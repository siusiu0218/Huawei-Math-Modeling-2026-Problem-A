## 已确认行为与口径问题

1. **重新插入已复现，正式配置影响未验证。** 600 bytes 的诊断 Cache 中，tensor 1001 在 t=210 命中，t=211 被 tensor 1004 淘汰，t=213 命中读取完成后重新插入，并淘汰 tensor 1004。原题 D.5 写明未命中读取完成后入缓存，没有明确规定命中后重新插入。代码 `multicore_cut_evaluate_problem_3.py:508` 对所有 COPY_IN 完成均调用插入函数。此处应标记为正文未明确覆盖的边界行为，不能仅凭诊断声称正式成绩错误。该时间线还显示 DDR 在 t=211 完成时 Cache 读取仍在运行，两个带宽池独立。
2. **官方搬运量与实际 DDR 流量须区分。** 延后读取算例实际读取 7200 bytes，其中 Cache 命中 600 bytes，DDR 读取为 6600 bytes；该小图无输出 COPY，故这里可以直接按读取求和。官方 `scheduled_copy_bytes` 在有/无 Cache 下均为 7200。原题把额外搬运描述为新增 DDR 字节，而代码在 Cache 模拟前计算搬运字段。保留官方字段原名，不把它用作实际 DDR 流量，也不将这个简化算式直接推广到所有图。
3. **补充验证（rules_remaining_20260926）：** 两次并发命中在 t=210 开始，共享 Cache 后均于 t=216 完成；本地 UB=120 bytes 的诊断中 spill 后逻辑 tensor 11 保持身份并命中；同一生产 tensor 被两个消费核读取时，后一次命中且跨核等待仍至少 500 cycles。原始非 DDR COPY 的统计边界仍未独立验证，故不据此解释实际 DDR 总流量。正式 1 MB 配置中是否观察到重新插入，将在基线事件统计中报告；其反事实性能影响未评估。

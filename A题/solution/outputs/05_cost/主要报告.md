## 观察

- case_046 有 8 个独立分量，候选按既有规则回退 v002。它不是新规则的有效验证：v005/v006 与基线的差异主要来自回退时的分核方案。
- case_048 是单连通图，但 v005 与 v006 的方案在四个核数均与彼此相同；在 v001 基线中其任务数为 8/12/16/20，候选为 1,245。成本门槛没有找到可合并的链边，任务碎片和搬运量都比 v001 增加；Makespan 在 n2 变慢、n3–n5 变快，不能把改善归因于任务合并。
- v006 将 Task 上限改为每核平均计算量后，在 case_048 上没有改变方案。对 case_016 的尝试因方案生成阶段过慢中断；经预建张量边界索引后的 v007 仅做计划生成检查，约 0.37 秒，但仍产生 10,675 个 Task（v004 为 7,015）。这不是性能对照，显示当前阈值仍未解决碎片化。
- 因此 v005/v006 不作为替代算法；目前没有证据证明提出的搬运/等待门槛能在目标连通图上同时减少碎片并改善 Makespan。新检验尚未进行。
- 开发固定：严格单入单出合并；等待期望按同核概率 1/k、跨核概率 (k-1)/k 估算；搬运用直接生产-消费张量字节数/60 bytes per cycle；v005 的计算上限为总工作量/(核数×4)，v006/v007 为总工作量/核数。

逐配置证据见 `comparison.csv`；每次运行的代码快照、方案、评估 JSON 与日志保存在各自实验目录。case_016 尚无本轮有效性能结果。

# 第二问算法说明：v007

本文件说明当前冻结方法的决策、约束与实际实现，供复现和后续论文写作使用。正式性能数值以全量报告为准。

## 模型与评价

将原图的非 COPY 计算操作记为集合 V，核心数 m 取 2、3、4、5。决定每个操作所属的子图 g(i)、每个子图所在核心 k(g)，以及每核子图优先顺序 π_k。输出对应 `node_to_subgraph` 和 `core_schedules`。

每个计算操作必须恰好属于一个子图；每个非空子图必须恰好安排到一个核心且出现一次。排序须满足真实数据依赖，并且核内 Pipe 顺序、内存复用依赖与跨核 COPY 共同形成的全局执行图不能有等待环。

令固定配置下原始场景 B 评估器给出的操作完成时间为 C_o，则目标为：

\[
\min_{g,k,\pi}\;T(g,k,\pi),\qquad T=\max_{o\in V\cup COPY\cup Spill}C_o.
\]

额外搬运量、方案生成时间和评估时间作为同时报告的指标，不擅自合成为题目未规定的加权总分。

对任一核心及任意时刻，驻留于 L1、UB 的有效数据和执行中预留空间不得超过各自容量 524288、131072 bytes。容量不足时，原始核内程序插入必要换出和换入；如果一个操作本身无法容纳，则方案不可执行。

场景 B 同核子图属于同一个 Task，子图边界不强制清空 L1/UB。跨核传输需满足：

\[
S_{\mathrm{COPY\_IN}}\ge C_{\mathrm{COPY\_OUT}}+500.
\]

所有核心共享 DDR 带宽 60 bytes/cycle。存在竞争时，COPY 时长取决于同时执行的传输，不能将每条边的“字节数 / 60”直接相加当作最终时间。各核心同一 Pipe 的指令按评估器确定的顺序串行，不同 Pipe 可以重叠。

上述模型通过合法候选生成与原始事件模拟求解，并未转化为精确求解器，也不主张得到全局最优解。

## 实际算法

1. 构造操作依赖图，保留经排除的 COPY 节点传递的依赖，求弱连通分量。
2. 先用场景 B 的区域方法生成基础方案：多分量图按计算量分组并分核；单连通图采用既有链/区域合并及依赖优先分配。目标块数倍率固定为 4，同核/跨核等待近似为 0/500。
3. 如果只有一个弱连通分量，直接输出基础方案。
4. 如果有多个分量，保留每个操作原来的核心归属。每核按基础子图顺序收集分量，同一子图内按分量最小操作编号排序。
5. 每次取两个分量，分别保留各自的确定拓扑序；交替取一个操作，为每个操作设一个子图优先级。较短序列结束后继续取另一序列，直到这对分量结束。
6. 检查操作覆盖与子图顺序合法性，输出一个候选方案，由原始问题 2 评估器检查全局执行合法性和容量、计算正式成绩。

基础区域方法中继承的“子图边界搬运”估计只是筛选启发式。第二问实际搬运取决于核心边界与缓存换入换出，因此该估计不是场景 B 的精确通信成本。正式搬运量与 Makespan 始终以原始评估器结果为准。

```text
base ← region_plan(G, m, blocks_per_core=4, waits=(0, 500))
components ← weak_components(compute_dependencies(G))
if count(components) ≤ 1:
    return base
for each core:
    sequences ← component_topological_orders_in_base_group_order(core)
    for each consecutive pair in sequences:
        interleave the two orders, preserving each order
        assign a separate subgroup priority to each emitted operation
validate coverage and subgroup dependency order
return plan
```

固定批大小 2 的动机是缩短共享输入的复用间隔，同时限制同时展开的分量数。它也可能增加同时驻留的中间数据，因此没有普遍提速保证。开发与新检验中观察到 spill 减少和部分配置提速，但不能据此推断所有输入都获益。

## 复现边界

代码：`solution/src/scene_b_paired_order.py`。冻结清单：`solution/experiments/problem2_v007_selection.json`。每方法每配置一个候选，生成 30 秒、评估 180 秒，无自动重试。全部参数在新检验之前固定，之后全量不按逐图成绩选择不同方法。

此方法与第一问 v009 的双候选择优不同：第二问 v007 内部不会评估两个候选后选较好者。v002 的额外全量运行用于比较，成本单独报告。

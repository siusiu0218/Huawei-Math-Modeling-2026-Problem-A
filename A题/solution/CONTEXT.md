## 第一问的关键规则

以下规则在 2026-09-24 的方案讨论中核对了[题目正文](../通用神经网络处理器下的多核调度问题.docx)、[固定配置](../data/config.txt)及[第一问评估器](../code/multicore_cut_evaluate_problem_1.py)相关逻辑；这不代表已经完整验证评估器。

- 一个子图就是一个 Task，子图数量不限，不要求等于核心数。
- 所有跨子图数据都经 DDR 中转，同一核上的不同 Task 也不保留彼此的私有缓存数据。因此，放到同核不等于省掉边界搬运，合并为同一子图才可能保留内部复用。
- 所有核心共享 DDR 总带宽 60 bytes/cycle；每核 L1 为 524288 bytes，UB 为 131072 bytes。
- 同核前一 Task 完成后至少等待 100 cycles；跨核前驱 Task 完成后至少等待 1000 cycles。任务需满足全部前驱与同核顺序约束，最早激活时刻取相应约束的最大值，不把各项等待简单相加。
- 我们输出操作到子图的映射 `node_to_subgraph` 和每核子图顺序 `core_schedules`。映射只覆盖全部非 COPY_IN/COPY_OUT 操作，每个操作恰好归属一个子图，每个子图恰好安排一次。
- 切分后的子图依赖图必须无环；加入同核顺序后也不能产生全局等待环。
- 核内操作排布、边界搬运和必要的缓存换入换出由题目程序处理。自编算法可以用近似成本筛选候选，但正式 Makespan 和额外搬运量必须由原始评估器在固定配置下给出。

## 候选改进算法（待实现、待验证）

第一版优先探索“考虑通信的子图合并 + 关键路径优先调度 + 局部调整”。记录这个方向不表示已经选定最终算法，也不预设它一定优于简单方法。

1. **合并候选：**优先考察紧密相连的计算链、传递大张量的生产者与消费者、共享大量输入的操作，以及可能利用不同计算流水线的操作。比较节省的搬运、损失的并行机会和缓存压力，不能只按通信量合并；合并后重新检查子图无环。
2. **分核与排序：**用到最终输出的剩余计算依赖链估计优先级，在前驱已安排的候选中调度；逐核估计空闲时间、前驱完成和等待约束，选择预计较早完成的位置。估计不替代共享带宽下的正式模拟。
3. **局部调整：**尝试合并相邻子图、拆分过大子图、迁移子图到其他核、调整无依赖冲突的顺序。先检查合法性，再比较评估结果，保存当前较好的可行方案。
4. **搜索预算：**记录候选数量与运行时间；比较时使用可比的搜索预算。块数、合并阈值、优先级公式和停止条件尚未确定，不针对用例编号硬编码。

## 跑出来看什么

- **方案能不能运行：**是否符合题目要求，评估器是否接受。
- **完成时间（Makespan）：**整张图从开始到结束需要多少周期；数值越小越快。
- **额外数据搬运量：**切图后比原图多搬了多少数据；通常希望越少越好。
- **找方案花的时间：**算法本身运行了多久；还要记录它试了多少个候选方案。

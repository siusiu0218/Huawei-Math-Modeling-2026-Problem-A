## 1 目标与执行边界

在场景 B 上研究共享只读 L2 对调度的影响，以 Makespan 为主指标，同时报告官方额外搬运量、按字节计算的 Cache 命中率、生成及评估耗时。正式配置固定为 L1 524288 bytes、UB 131072 bytes、DDR 60 bytes/cycle、L2 1048576 bytes、L2 250 bytes/cycle、跨核 COPY 等待 500 cycles。

允许优化非 COPY 操作的子图归属、子图分核、各核子图顺序；不直接控制 COPY 发射时刻，不更改原图、固定配置、FIFO 策略或原始评估器。子图先后顺序不等于所有不同 Pipe 操作完全串行，是否改变读取时机必须看原始时间线。

正式实验使用全部 100 张图及 1～5 核。第三问主要加速比是同图同核数的无 L2 Makespan / 有 Cache Makespan，不沿用前两问单核 / 多核的定义。参数变化只能用于明确标注的机制诊断，不混入固定配置正式成绩。

本计划依据原题问题 3、附录 D、data/config.txt、code/multicore_cut_evaluate_problem_2.py 和 code/multicore_cut_evaluate_problem_3.py。原始材料只读；第一、二问成果保留。疑似评估器错误先记录并讨论，不自行修复原件。

### 阶段 0 核对规则与指标

输入：原题、固定配置、原始评估器及上一轮初读发现。

工作：用可手算小图逐项检查以下行为，记录预期值、实际值、操作时间线和 Cache 事件。

1. 空 Cache 首次读取未命中，完成后入缓存；后续读取命中且不进入 DDR 带宽池。
2. 两核同时首次读取同一 tensor 时，第一次尚未完成，两次均可未命中；不假设评估器合并请求。
3. 普通命中不更新 FIFO 顺序；容量不足按插入顺序淘汰；单 tensor 超容量不缓存。
4. 命中读取进行中条目被淘汰，完成时是否重新插入、是否影响后续读取。2026-09-26 已在缩小容量诊断中复现命中完成后重新插入；用户已决定沿用原始评估器并披露该行为，不能据此泛称正式成绩错误。
5. DDR 和 Cache 带宽池彼此独立、池内共享；检查 COPY_OUT 不主动填充 Cache，以及命中不能跳过跨核 500 cycles 等待。
6. 逻辑 tensor id 在跨核及 spill 后的识别是否一致；核内非 DDR COPY、零字节 COPY 是否参与命中统计。将实际代码行为与正文范围分开记录。
7. 以不等大小的命中和未命中读取验证字节命中率；没有有效访问时核对零值约定。
8. 核对官方搬运量是否独立于命中，并用明确发生命中的小图对照实际 DDR 流量。不能直接用“官方总搬运量减 hit_bytes”作为通用公式，须先核对统计范围与逐操作字节数。

已知口径差异：代码在 Cache 模拟前统计 data_movement_bytes，未扣除 Cache 命中的读取；正文将其描述为新增 DDR 搬运量。正式表保留官方字段，另设清楚命名的辅助 DDR 指标，不能静默更换定义。

产出：规则核验脚本/测试、完整原始 JSON、规则核验报告、问题清单。问题清单分别标为“已验证一致、已确认差异、存在歧义、未验证”，记录源码位置和影响。

完成门槛：关键分支有算例证据；涉及正式结论的口径明确。若复现会影响评分的正文/代码冲突，先提交最小证据与处理选项讨论；独立诊断可继续，冲突未解决前不宣布正式评估口径已定。

### 阶段 3 建立开发集成对基线

使用第二问冻结 v011 最终方案作为多核起点，一核使用明确归档的单核方案。2026-09-26 经用户同意启动前更新：第二问当前正式版本已从 v007 推进到 v011，因此更新基线来源。第二问版本号是来源标识，第三问另立自己的算法版本并记录来源哈希。复用方案的历史生成和候选评估成本须单列，不记作零成本。

| 组别 | 方案 | 评估条件 | 用途 |
|---|---|---|---|
| A | 第二问固定方案 | 无 L2 | 成对参照 |
| B | 与 A 完全相同 | 有 Cache | 衡量固定方案增加 Cache 的效果 |
| C | 第三问优化方案 | 有 Cache | 后续衡量调度优化收益 |
| D | 与 C 完全相同 | 无 L2 | 区分新方案的一般调度收益与 Cache 相关收益 |

本阶段先完成 A/B，每张开发图覆盖 1～5 核。旧 A 成绩只在输入、配置、方案、评估源码和结果哈希一致且口径兼容时复用，否则重新运行并保留新记录。

逐项检查：Makespan、官方搬运量、命中/未命中字节、访问次数、Cache 插入/淘汰事件、容量峰值、跨核等待、生成与评估时间。无 L2 命中率写“不适用”，不伪装为一次 Cache 测量得到的 0。

产出：逐图配对表、开发集报告、代表性时间线；判断瓶颈属于缺少复用、读取过早、提前淘汰、带宽争用、计算或依赖限制。不能只凭命中率低就认定应优化 Cache。

完成门槛：所有计划配对有明确状态；收益、无收益及退步均保留，诊断可指向具体操作或事件。

### 阶段 4 分步优化与消融

先固定分核，只改变合法子图顺序；尝试让共享输入的使用集中在合适时间窗口，减少复用前的无关数据插入。评估器可能提前发射 COPY，必须验证实际读取时刻，不人为添加方案格式不支持的延迟。

若排序收益有限，再研究共享数据相关的分核移动或局部合并，同时约束负载失衡、依赖路径增长和私有缓存压力。每版只引入可解释的改动，算法改变即递增第三问版本。

用轻量代理筛选候选，最终优劣由原始评估器 Makespan 决定。代理可考虑共享字节、复用窗口、预计新插入字节及计算负载；FIFO 不能套用“每次命中刷新”的 LRU 模型，代理也不是命中保证。

每版保存完整候选数、搜索耗时、失败和退步。多候选择优须披露所有评估成本；除与固定起点比较外，应有匹配预算的搜索对照，不能将更多试验机会冒充算法本身优势。

完成 A/B/C/D 对照：A/B 为旧方案 Cache 效果，B/C 为 Cache 条件下优化效果，D/C 为新方案 Cache 效果，A/D 为无 Cache 条件下的方案变化。比值不能简单相减后声称为独立因果贡献。

完成门槛：开发对照和必要消融齐全，保留或放弃的理由有实测依据；没有改善也可以冻结可靠基线，不强行保留复杂方法。

### 阶段 5 冻结与预留图检验

运行前冻结算法、参数、候选预算、依赖源码哈希和单核处理规则。对预留图完成相同核数与比较组，不按 case 编号选择方法，不按检验成绩改参数。

若根据检验结果调整，当前检验图转为开发图，另选未用于第三问调整的图并留痕；无剩余图时明确没有新的独立检验，不能反复更名。

完成门槛：检验结果、失败/超时、退步幅度、额外成本全部报告，确定全量版本。冻结不意味着保证每图改善。

### 阶段 6 全量与交付核对

覆盖全部 100 张图 × 1～5 核。最终优化方案必须有同方案无 L2/有 Cache 的 500 对结果；为说明从第二问起点的改进，保留 A/B 对照。若 A/B/C/D 均独立运行，最多为 2000 次评估；方案或已存结果完全一致时允许核验后去重复用，并逐项记录来源，不把复用算作新增运行。

逐图先计算比值，再按核数取算术平均；同时报告样本数、快/平/慢数量、最差退步和失败。该均值是本研究明确采用的汇总约定，不声称正文已规定全部聚合细节。正文主曲线展示同方案无 L2 与有 Cache 的可比较指标，并报告同核数 Cache 加速比；两方案的端到端变化另标注。

命中率逐用例报告；跨图汇总分别命名“逐图字节命中率平均值”和“汇总命中字节/汇总访问字节”，不可混用。任何配对缺失均单列，不把成功子集称为完整 100 图结果。

交付：正文图表、逐图指标表、方案包、完整结果索引、源码快照、复现命令、完成核对记录。独立复算比值和均值，检查全量覆盖、方案合法性、容量与等待约束、哈希及图形可读性。算法求解秒数与模拟 Makespan cycles 分开。

完成门槛：全部计划配置成功或明确列出未完成项；正式完成要求题目所需覆盖齐全、关键歧义已处理、结果可复现。未经验证不能称最优，也不保证加 Cache 在每个调度方案上必然加速。

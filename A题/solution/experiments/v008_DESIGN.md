# v008：小分叉与汇合合并的成本规则

从冻结 v004 的分区开始，保留其多分量回退、关键路径调度与倍率4。
算法不读取用例编号或性能结果。开发图为已看过成绩的 case_016/069。
固定参数及源码哈希见 `v008_selection.json`；正式效果以原始评估器为准。

## 张量边界搬运

每个张量 t 维护当前生产 Task 集合 P、消费 Task 集合 C，及原图是否含 COPY_OUT。
输入 COPY 数为 `|C - P|`；对每个生产 Task p，原图要求 COPY_OUT、没有计算消费者、
或存在其他 Task 消费时，计一次输出 COPY。次数乘张量大小就是当前 Task 图的搬运量。
这复现第一问评估器 `_build_scene_a_tasks` 的边界判定，不包含后续容量溢出。

合并集合 R 后，把 P/C 中属于 R 的 Task 统一替换为新 Task，重新计数。
只检查 R 触及的张量，每个张量只计一次。共享输入、外部消费者、原始 COPY_OUT
都保留相应费用；原图已有 COPY 总量在分区前后相同，因此比较差值时抵消。

手算边界：

- A→B 的张量60 bytes、B→C 的张量120 bytes：先合并 A/B 省120 bytes，
  再把 C 合入省240 bytes。不能用代表操作 A 查询 A→C 后漏算 B 的输出。
- A 的60 bytes张量被 B/C 同时消费：三Task共180 bytes；合并 A/B 后仍需
  对 C 输出和输入，共120 bytes，仅省60。再合并 C 才省余下120。
- 题目原有输出 COPY 在合并后继续计入。

## 小分支端点合并

仅检查当前 DAG 中 `u只有一个后继` 或 `v只有一个前驱` 的边 u→v，
该条件排除 u 到 v 的其他路径，收缩后不会产生依赖环。

- v 是汇合点时，把 u 合入 v，u 可能被迫等待 v 的其他输入；计算关键路径
  增量上界记为 `work(u)`。
- u 是分叉点时，把 v 合入 u，u 的其他输出可能被 v 延迟；增量上界为 `work(v)`。
- 普通串行连接的增量为0。不能用两个端点的较小计算量替代上述有方向的上界。

当增量上界小于 `省下的边界字节/60 + min(同核等待,跨核等待)`，
且合并工作量不超过 `总计算量/(核数×4)` 时接受。合并后立即更新 Task 邻接和
张量生产/消费集合，再考虑受影响的边。

等待项是局部筛选代理：固定配置下为100 cycles，不把可能重叠的所有等待相加，
不假设核心均匀随机分配。它不是全局 Makespan 收益保证。

## 闭合分叉区域

从分叉根展开，只接纳全部前驱已经在区域内的节点。当前所有出口汇为一个节点时，
得到入口/出口明确、依赖路径闭合的区域。有额外入口、提前遇到独立终点、超过128个
Task或计算上限时不合并。最多3轮扫描。

区域串行工作量减去其最长计算路径，是使用求和计算代理时的并行损失。
将最小等待加入区域内部依赖，分别求最长路径，差值为等待收益代理。
只有并行损失小于等待收益加边界搬运收益时接受。最终方案仍由原验证器检查。

## 已检查的边界与限制

26项测试通过，包括连续两次合并、共享张量保留外部消费者、原始输出 COPY、
短/长菱形、短汇合树、外部入口/多个出口、随机 DAG 的合法性及输入不变性。
小图搬运字节还与原始评估器核对；开发/检验报告继续逐配置核对边界总量及差值。

`work` 把不同流水线计算周期相加；真实核内重叠、L1/UB溢出、共享带宽竞争及
同核排序效应仍由原始评估器模拟。局部收益可被外部依赖遮蔽，规则不保证普遍提速。
当前没有共享输入跨迭代重排、完整搜索或最优性保证。
